DockSlate 0.1.0 · Windows

다운로드 · 사용 안내 · 작업 현황

시작하기컨테이너이미지 · 실행 설정파일로 빌드볼륨 · 네트워크설정 · 디스크자주 묻는 질문요청별 작업 현황

Docker Engine을 DockSlate에서 설치하고 사용합니다.

Linux용 Docker Engine은 전용 WSL 2 안에서 실행됩니다. Windows 앱에서 엔진을 설치하고, 컨테이너·Dockerfile·Compose를 관리합니다.

설치판·ZIP 제공 중단

설치판은 앱과 Windows 명령 진입점을 설치하고 Docker Engine 설치 대상을 확인합니다. 대상과 영향에 동의하면 엔진·Compose·Buildx 설치와 시작, Windows 명령 검증을 자동으로 진행합니다. Node.js와 Rust는 필요하지 않습니다.

현재 파일은 미서명입니다. 정식 서명과 보안 확인 전까지 설치판·ZIP 다운로드를 제공하지 않습니다.

설치판과 ZIP에는 공식 Windows Docker CLI·Compose·Buildx를 포함합니다. 설치 파일 생성·해시 대조와 기존 엔진의 CLI·Compose 실행을 확인했으며, 실제 설치·제거 검증은 남아 있습니다.

서명·보안 확인 미완료. 이전 브라우징 데이터 접근 경고의 원인은 미확인입니다. 코드 서명은 게시자와 무결성을 확인하며 악성코드 검사를 대신하지 않습니다. 보안 예외·신뢰 등록은 하지 않았습니다.

필요한 환경

  • Windows 11 x64
  • WSL 2.4.10 이상
  • Microsoft Edge WebView2 Runtime
  • 엔진 최초 설치 시 인터넷 연결

처음 사용하는 PC

  1. 설치판으로 앱과 Windows CLI 설치
  2. 설치 중 열린 엔진 준비 화면에서 Docker Engine 설치 및 시작 승인
  3. 엔진·Windows CLI·Compose·Buildx 확인 → 설치 완료
  4. 새 터미널에서 docker ps, docker compose version 사용

엔진은 공식 패키지를 내려받아 설치합니다. 기존 DockSlate 엔진은 등록 경로와 소유권을 검사해 재사용하며 WSL을 삭제하지 않습니다. 실제 설치·제거 검증은 남아 있습니다.

index.html과 dist/index.html은 왜 앱으로 실행되지 않나요?

두 파일은 Tauri가 띄우는 화면의 진입점입니다. 브라우저의 file:// 주소에는 Rust 백엔드가 없으므로 엔진을 제어할 수 없습니다. 직접 열면 이 안내서로 이동할 수 있게 했습니다. 개발 화면은 npm run dev, 데스크톱 개발 실행은 scripts/desktop.ps1 -Mode dev를 사용합니다.

컨테이너 확인

표의 열 경계선을 드래그하면 너비가 저장됩니다. 키보드 방향키로도 조절하며 Enter 또는 더블클릭으로 기본값을 복원합니다. 포트를 누르면 접속 주소를 복사합니다.

  1. Containers에서 이름 클릭
    항상 같은 크기의 중앙 팝업이 열립니다. 긴 내용은 내부에서 스크롤합니다.
  2. 상세 / 로그 / 상세 JSON / 마운트 / 터미널 / 파일
    CPU·메모리는 상세 탭을 열 때 한 번 읽습니다. 다시 확인하려면 ‘다시 측정’을 누릅니다.
  3. 시작·중지·재시작은 목록 오른쪽 메뉴
    브라우저에서 열기는 연결된 포트가 있는 경우 사용할 수 있습니다.
할 일위치와 동작
로그 확인처음에는 최근 300줄을 받고 이후 새 로그를 감지합니다. 검색·복사·자동 스크롤 지원. 탭을 닫으면 연결도 닫습니다.
파일 탐색왼쪽 폴더 트리 → 오른쪽 목록 → 파일 미리보기. 폴더를 펼칠 때 필요한 경로만 읽습니다.
터미널 연결실행 중인 컨테이너에서 /bin/sh 또는 /bin/bash 선택. 셀이 없는 이미지는 연결할 수 없습니다.
설정 확인상세 JSON에서 검색·영역 선택·복사. 마운트 탭에서 실제 연결 경로를 확인합니다.
시작했는데 바로 중지되는 건 오류인가요?

hello-world처럼 메시지를 출력하고 끝나는 이미지는 정상 종료해도 중지 상태가 됩니다. 상세의 종료 코드가 0이고 로그에 정상 출력이 있으면 프로그램이 끝난 것입니다. 계속 실행하려면 서버 등 계속 동작하는 프로세스를 가진 이미지가 필요합니다.

이미지에서 실행

  1. 이미지 준비
    Images → Docker Hub에서 검색·Pull하거나 로컬 이미지를 선택합니다. Pull 팝업에 실제 레이어 진행 상태를 표시하고, 완료 후 닫기 버튼을 누릅니다.
  2. 실행 설정 입력
    선택한 이미지 행 바로 아래에 실행 설정이 열립니다. 이름과 포트를 지정합니다. ‘더보기’에서 볼륨·네트워크·환경 변수·명령·작업 경로·재시작 정책·CPU·메모리를 설정합니다.
  3. 실행 명령어 확인
    Docker(WSL) 명령을 기본으로 표시합니다. Windows에서 호출할 PowerShell 7.3+ 형식도 복사할 수 있습니다. 미리보기는 자동 실행하지 않습니다.
  4. 컨테이너 생성 및 실행
    컨테이너 목록으로 이동해 새 행을 표시합니다. 상세 팝업은 이름을 눌렀을 때만 엽니다.
참조 중인 이미지 삭제는 승인창에서 ‘참조 컨테이너도 함께 삭제’를 직접 선택해야 합니다. 중지·생성·dead 상태만 허용하며, 볼륨은 남깁니다. 실행 중 참조와 여러 태그가 있는 이미지는 차단합니다.
명령어가 docker로 시작하지 않는 이유는?

기본 Docker 탭은 전용 WSL 내부에서 실행하는 docker 명령입니다. PowerShell 탭은 Windows에서 wsl.exe를 거쳐 같은 엔진의 Docker를 호출하므로 더 깁니다. Windows에 별도로 설치한 docker.exe가 다른 엔진에 연결되는 것을 피하기 위한 형식입니다.

Dockerfile · Compose로 빌드

입력사용 순서
DockerfileBuilds → 파일 가져오기 → Dockerfile 선택. 파일이 있는 폴더를 빌드 컨텍스트로 사용합니다. COPY가 참조하는 소스도 그 폴더 안에 있어야 합니다.
compose.yaml / yml파일 선택 → 검증 → 빌드 → 서비스·이미지·포트·볼륨·네트워크 확인 → 실행 승인.
컨텍스트 직접 지정이미지 빌드 폼에서 폴더·Dockerfile 경로·이미지 태그를 지정합니다.
.dockerbuild빌드 기록 가져오기·내보내기용입니다. 이미지나 빌드 캐시를 복원하지 않습니다.

파일은 외부 서버로 업로드하지 않고 전용 WSL 엔진에서 처리합니다.

Compose 가져오기 제한
  • 1~16개 서비스, 프로젝트 폴더 안의 상대 빌드 경로
  • 새 이름의 볼륨과 bridge 네트워크
  • include·extends·env_file·변수 치환·secrets·configs 미지원
  • 호스트 bind mount·privileged·장치·외부 리소스 미지원

새 파일 선택 → 빌드 → 실행 UI 경로는 코드·컴파일 확인까지 끝났으며, 실제 엔진 E2E 검증은 남아 있습니다. 이전의 격리된 두 서비스 Compose CLI 빌드 성공과 구분합니다.

볼륨 · 네트워크

Resources → Volumes

  • 생성·복제·참조 확인
  • 파일 탐색·텍스트 보기
  • tar 내보내기·병합 / 교체 가져오기
  • 비우기·삭제는 영향 확인 후 승인

Resources → Networks

  • driver·IPAM·참조 컨테이너 확인
  • bridge·내부 전용 네트워크 생성
  • 기본 네트워크 삭제 차단
  • 참조 없는 사용자 네트워크만 삭제
볼륨을 만들면 기존 컨테이너에 연결되나요?

생성만으로는 연결되지 않습니다. Images의 실행 설정에서 볼륨을 선택하고 컨테이너 내부 경로를 입력해야 합니다. 같은 화면에서 새 볼륨·네트워크를 만들고 선택할 수도 있습니다. 기존 컨테이너의 볼륨 마운트를 바꾸려면 컨테이너를 새 설정으로 재생성해야 합니다.

전체 새로고침과 메뉴 이동의 차이

메뉴 이동은 저장된 조회 결과를 사용합니다. 전체 새로고침과 생성·삭제 같은 작업이 결과를 갱신합니다. 열린 로그는 Docker 스트림으로 새 내용을 받고, 터미널·진행 중 작업만 필요한 갱신을 수행합니다.

자주 묻는 질문

MongoDB가 실행 중인데 Compass에서 연결이 거절돼요.

컨테이너 포트와 PC 포트를 구분해야 합니다. 표가 127.0.0.1:32768 → 27017/tcp라면 Compass 주소는 mongodb://127.0.0.1:32768/입니다. 표의 포트를 눌러 주소를 복사하세요. MongoDB 포트는 웹 페이지가 아니므로 브라우저에서 열지 않습니다. 자동 할당된 PC 포트는 컨테이너마다 다를 수 있습니다.

Windows에서 docker 명령은 어떻게 쓰나요?

설치판은 현재 사용자 PATH에 DockSlate의 bin 폴더를 등록합니다. 설치 후 새 CMD·PowerShell 창에서 아래 명령을 사용하세요. 포터블은 전체 ZIP을 푼 폴더의 bin\docker.exe를 실행합니다. 개발 PC의 파일 복사 접근 거부와 실제 설치·빌드 검증은 남아 있습니다.

docker ps
docker build -t my-app .
docker compose up -d

설치 과정에서 엔진 준비와 Windows 명령 검증을 함께 진행합니다. 기존 WSL과 이미지는 유지합니다. 새 포터블 구성에는 ZIP 안의 bin·libexec 폴더도 필요합니다. Windows SDK는 현재 사용자 전용 pipe를 명시해야 하며 실제 호환성 검증은 남아 있습니다.

앱을 지우거나 다시 설치하면 WSL 데이터도 없어지나요?

앱 EXE·설치 폴더와 전용 WSL 배포판은 별개입니다. 포터블 EXE 삭제나 앱 제거로 WSL 배포판·이미지·볼륨을 자동 삭제하지 않습니다. 런타임 중지도 데이터를 지우지 않습니다. 재설치 후 기존 배포판의 소유권과 엔진 정보를 확인해 사용합니다.

deployment.yaml 하나로 전체를 빌드할 수 있나요?

파일 이름이 아니라 내용으로 구분합니다. Docker Compose 형식이면 제한된 Compose 가져오기 대상으로 사용할 수 있습니다. Kubernetes Deployment 형식은 이미 만들어진 이미지를 실행하는 선언이라 Dockerfile 빌드 입력이 아니며, DockSlate는 Kubernetes 배포를 지원하지 않습니다.

Apple container나 Davit을 적용할 부분은?

이 Windows 앱의 엔진을 macOS 전용 Apple container로 교체할 수는 없습니다. 화면 밀도·탭·작업 중심 배치는 참고할 수 있습니다. 저장소와 빌드 소스를 Linux 파일 시스템에 두어 Windows↔WSL 경계를 줄이는 방향은 검토할 수 있지만, 이 프로젝트에서 I/O 개선 수치를 측정하지는 않았습니다.

보안 경고는 해결됐나요?

아직 아닙니다. 소스에서 일반 Chrome·Edge의 기록·비밀번호 파일을 읽는 코드는 발견하지 못했지만, 그것만으로 실행 파일의 안전을 확정할 수는 없습니다. WebView2는 앱 전용 프로필을 사용합니다. 실제 경고가 가리킨 접근 대상 경로가 없어 원인은 미확인이고, Defender 검사는 기능 비활성화로 실행되지 않았습니다.
