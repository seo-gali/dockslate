# DockSlate 사용 안내

[다운로드](https://seo-gali.github.io/dockslate/) · [사용 가이드 영상](https://youtu.be/EbL7LkbNrPY) · [지원·검증 현황](REQUEST_STATUS.md)

이 안내는 0.1.17 소스 기준입니다. 프로젝트 일괄 실행·설정만 Compose로 가져오기·이전 시간 제한 및 오류 안내 개선을 포함합니다. 실제 공개 파일은 [홈페이지](https://seo-gali.github.io/dockslate/)에서 확인하세요.

## 트레이

창의 X를 누르면 시계 옆 트레이로 숨깁니다. 아이콘 왼쪽 클릭은 창을 다시 열고, 오른쪽 메뉴에서 열기·컨테이너·이미지·전체 새로고침·설정·완전 종료를 선택합니다. 완전 종료해도 Docker Engine과 컨테이너는 계속 실행됩니다. 빌드·전송 등 작업 중에는 종료를 막고 진행 상태를 표시합니다.

## 설치와 엔진

Windows 11 x64·WSL 2.4.10+·WebView2가 필요하며 최초 엔진 설치에는 인터넷이 필요합니다. 설치 EXE에서 앱·Windows CLI를 준비한 뒤 엔진 대상과 영향을 확인해 승인합니다. 포터블은 ZIP 전체를 풀고 `DockSlate.exe`·`bin`·`libexec`를 함께 유지합니다.

Docker Desktop·Rancher Desktop의 기존 데이터는 자동으로 이관하지 않습니다. Compose 파일 편집·기존 프로젝트 교체·Kubernetes 배포는 지원 범위에 포함하지 않습니다.

**설정 → 데이터 가져오기**를 열어 Docker Desktop Linux 엔진의 이미지·컨테이너·볼륨과 연결된 파일·폴더를 복사합니다. 양쪽 엔진을 켠 뒤 목록을 조회하고 전체·프로젝트 또는 개별 항목을 선택해 **가져올 대상 검사**를 누르세요. 승인창에서 정상 중지할 원본·복사할 데이터·시작할 복사본을 확인합니다. **실행 중인 원본 정상 중지**와 **원래 실행 상태 유지**는 기본으로 켜져 있습니다. 이미지를 먼저 복사하고 선택한 원본을 정상 중지한 뒤 파일·볼륨·컨테이너를 복사합니다. 모두 끝나면 원래 실행 중이던 복사본만 시작합니다. 실행 상태 유지를 끄면 복사본은 중지 상태입니다.

컨테이너·볼륨·이미지 태그 충돌은 덮어쓰지 않습니다. 이전 이력과 설정이 같은 네트워크를 재사용하며, 완료 기록과 실제 대상을 확인한 항목은 숨기고 완료 볼륨을 재사용합니다. 연결된 파일·폴더는 별도 볼륨에 복사되므로 원래 호스트 폴더와 이후 동기화되지 않습니다. [가져오기 범위와 순서](MIGRATION.md)를 확인하고 복사본의 서비스·데이터를 검증한 뒤 Docker Desktop을 제거하세요. 실제 두 엔진 사이의 전체 이전 검증은 남아 있습니다.

데이터 복사 대신 **설정만 Compose로 가져오기 → Compose 설정 검사**를 사용할 수도 있습니다. 컨테이너 1~16개의 실행 설정을 새 프로젝트로 변환하며 원본은 중지하지 않습니다. 같은 이미지 ID가 DockSlate 엔진에 있어야 하고 이미지·쓰기 계층·볼륨 데이터는 복사하지 않습니다. 볼륨은 새 빈 볼륨으로 만듭니다. 파일·폴더 bind 등 미지원 설정은 차단합니다. **실행 미리보기**에서 새 리소스와 포트를 확인하고 별도로 실행을 승인하세요. [설정만 가져오기](MIGRATION.md#설정만-compose로-가져오기)에 제한을 정리했습니다.

설정의 **런타임**에서 실제 위치·상태를, **엔진 연결 정보**에서 엔진·API 버전을 확인합니다. Moby는 Docker의 오픈소스 기반입니다. 앱·Docker Engine·Microsoft WSL 커널 업데이트는 별개이며 현재 앱은 API 1.55를 상한으로 협상합니다.

현재 소스의 **설정 → 자동 시작**에는 **DockSlate 실행 시 엔진 시작**, **Windows 로그인 시 엔진 시작**, **Windows 로그인 시 DockSlate 창 열기**가 있습니다. 앱 실행 시 엔진 시작은 기본 활성화이며 설치·소유권 검증을 마친 전용 엔진만 시작합니다. 미설치 엔진을 자동 설치하지 않습니다. Windows 로그인 설정은 기본 해제이며 명시적으로 선택해야 등록합니다. 엔진만 로그인 시작하면 창을 열지 않습니다. 앱 시작 시 엔진 시작을 끄더라도 로그인 시 엔진 시작을 선택했다면 로그인 때는 엔진을 시작합니다. 컨테이너는 Docker 재시작 정책을 따릅니다. 포터블을 옮기기 전에는 기존 위치에서 로그인 자동 시작을 끄고 새 위치에서 다시 설정하세요.

신규 엔진의 기본 데이터 위치는 `%LOCALAPPDATA%\DockSlateData\runtime\wsl`입니다. 기존 `DockSlate` 등록이 있으면 등록 경로와 소유권을 확인해 사용하며 자동으로 새 위치로 옮기지 않습니다.

앱 제거는 WSL 등록·이미지·볼륨을 자동 삭제하지 않습니다. 앱 폴더를 수동으로 지우기 전 런타임 위치를 확인하세요. 그 아래에 엔진 데이터나 수동 커널을 두었다면 함께 지워질 수 있습니다. 기존 이름의 WSL 등록에 소유권이나 VHDX가 없으면 앱이 재사용을 차단하며 자동으로 등록을 해제하지 않습니다. 필요한 데이터의 복구 여부와 실제 대상을 확인한 뒤 별도로 복구합니다.

## 이미지와 컨테이너

1. **이미지 → Docker Hub → 검색 → 선택 → 태그 확인 → Pull 실행**으로 이미지를 받습니다.
2. **로컬 이미지 → 실행**에서 이름·컨테이너 포트·내 PC 포트와 연결 설정을 확인합니다. **실행 명령어 확인**은 Docker(WSL)·PowerShell 7.3+ 명령을 표시하며, **컨테이너 생성 및 실행**이 실제 작업을 수행합니다.
3. **컨테이너** 목록에서 상태·포트·CPU·메모리를 확인하고 이름을 눌러 상세·로그·상세 JSON·마운트·터미널·파일을 엽니다. 실행 중인 컨테이너에서 터미널에 연결할 수 있습니다.

Compose 그룹과 단독 컨테이너 그룹은 제목을 눌러 접고 펼칩니다. Compose 그룹의 **시작·중지·재시작**은 검색·페이지에 가려진 항목까지 같은 프로젝트에 적용하며 일회성 컨테이너를 제외한 1~256개가 대상입니다. 시작은 Compose 의존 라벨의 순서·조건을 따르고 중지는 역순으로 진행하며, 재시작은 역순 중지 후 순서대로 시작합니다. 의존 서비스 누락·순환이나 실행 실패가 있으면 후속 단계를 멈춥니다. 기존 컨테이너를 제어하며 프로젝트를 새로 만들지는 않습니다.

컨테이너 내부 포트는 같아도 되지만 같은 호스트 주소의 공개 포트는 서로 달라야 합니다. `127.0.0.1:18080 → 8080/tcp`는 내 PC의 18080 포트로 접속합니다.

행 체크박스로 여러 컨테이너를 고르고 **시작·중지·재시작**할 수 있습니다. 머리글 체크박스는 검색·상태 필터에 맞는 모든 페이지를 선택합니다. 검색·필터를 바꾸면 선택을 해제하고 정렬은 선택을 유지합니다. 한 번에 최대 256개이며 상태가 맞지 않는 대상은 건너뜁니다. 일부 실패하면 사유를 확인하고 선택 상태로 남은 실패 항목만 다시 처리하세요. 데이터 가져오기 선택 한도 4096개와는 별개입니다.

시작·중지 작업은 행에 **대기 중·작업 중**으로 표시합니다. 다른 컨테이너의 작업은 대기열에 추가할 수 있고 목록·상세 조회도 계속 사용할 수 있습니다. 같은 대상의 중복 작업과 진행 중 삭제·수정·엔진 중지는 차단합니다. 개별 시작·중지 API 요청은 최대 120초를 기다립니다. 프로젝트의 건강 상태 대기는 healthcheck의 시작 유예·간격·제한 시간·재시도 수를 반영해 2~30분으로 정하며, 성공 종료 조건은 최대 30분 기다립니다. API 요청 제한과 프로젝트 전체 작업 시간을 구분하고, 실패·시간 초과 시 실제 상태를 다시 확인하세요.

**자동 시작 켜기**는 선택한 컨테이너의 Docker 재시작 정책을 `always`로, **자동 시작 끄기**는 `no`로 바꿉니다. 컨테이너를 재생성하거나 즉시 시작·중지하지 않습니다. `always`는 엔진 재시작과 컨테이너 종료 때 다시 실행하며, 수동 중지한 컨테이너도 다음 엔진 시작 때 실행합니다. 한 번도 정상 실행한 적 없는 컨테이너는 먼저 직접 시작해야 합니다. Compose로 다시 만들면 Compose 파일의 정책이 적용됩니다. [Docker 재시작 정책](https://docs.docker.com/engine/containers/start-containers-automatically/)이 기준입니다.

이미지·컨테이너 삭제 승인창에서는 삭제가 막힌 항목을 제외하고 나머지를 다시 검사할 수 있습니다. 다중 태그 이미지는 승인창의 태그·digest를 강제 삭제 없이 해제합니다.

**작업 → 수정…**에서 이름·포트·네트워크·볼륨을 변경합니다. 이름만 바꾸면 ID와 실행 상태를 유지합니다. 연결 변경은 승인 후 재생성하며 기존 쓰기 계층 파일을 로컬 이미지에 보존하고 볼륨을 유지합니다. 로그·프로세스 상태는 이전하지 않습니다. Compose·Swarm·고정 IP 등은 이름 변경만 지원하며 나머지는 원본 프로젝트에서 수정합니다.

## Dockerfile과 Compose

**빌드 → 파일에서 빌드 → Dockerfile 선택 / Compose 파일 선택**에서 시작합니다. 파일 선택 직후 빌드가 시작되며 Dockerfile의 **다시 빌드**로 재실행합니다. 한 카드에 선택한 형식의 설정·결과만 표시하고 **파일 선택 닫기**는 오른쪽 아래에 있습니다. 빌드만으로 컨테이너가 실행되지는 않습니다.

직접 선택할 예제는 [examples/basic-web](../examples/basic-web/README.md)입니다. `Dockerfile`·`compose.yaml`·`server.mjs`·`.dockerignore`를 같은 폴더에 두세요. Dockerfile은 부모 폴더를 빌드 컨텍스트로 사용하므로 `COPY`할 소스도 그 안에 있어야 합니다. 완성 이미지는 로컬 이미지에서 실행합니다.

Compose는 빌드 후 **실행 미리보기**에서 서비스·포트·새 볼륨·네트워크와 영향을 확인해 별도로 실행을 승인합니다. 예제 실행 후 `http://127.0.0.1:18080`에서 확인합니다. 충돌 방지용 `dockslate-import-…` 내부 이름은 상세에서 확인하고 목록에는 짧은 표시명을 사용합니다. 로컬 프로젝트 안의 상대 빌드 컨텍스트·새 이름 있는 볼륨·bridge 네트워크를 지원합니다. 환경 변수 치환·env_file·secrets·외부 리소스·bind·privileged·장치 연결은 가져올 수 없습니다.

**진행 중인 빌드**는 현재 작업을, **빌드 기록**은 완료·실패 이력을 보여 줍니다. **빌더 관리**는 다음 빌드에 사용할 Docker·BuildKit 환경을 선택합니다. **가져온 기록**은 `.dockerbuild` 보관 기록이며 이미지·빌드 캐시를 엔진에 복원하는 기능이 아닙니다.

## 리소스와 디스크

**리소스 → 볼륨 / 네트워크**에서 참조 컨테이너 이름·상태를 확인합니다. 볼륨 생성과 컨테이너 연결은 별개입니다. 기존 컨테이너 연결 변경은 수정·재생성 절차를 사용합니다. 기본 네트워크와 참조 중인 네트워크는 삭제할 수 없습니다.

**디스크 관리 → Docker 사용량**의 헤더 체크박스는 현재 검색·필터 결과에서 선택 가능한 대상만 선택합니다. 선택 가능은 조회 시 조건 통과이며 실행 직전 다시 검사합니다. 이미지와 공유하는 캐시·다른 캐시가 참조하는 부모는 유지하며, 조회 실패로 과거 정보만 남으면 정리할 수 없습니다.

정리에는 별도 승인이 필요하고 처리 건수·현재 대상·경과 시간이 표시됩니다. 전체량을 모르면 불확정 진행 표시를 사용합니다. 일부 실패 시 **실패 항목 보기**에서 한국어 사유를 읽고 목록을 다시 조회하세요. 컨테이너·볼륨을 자동 정리하지 않습니다.

**WSL 디스크**의 공간 회수는 ZIP 압축과 다릅니다. 안전 조건을 확인한 대상의 비어 있는 블록을 회수하며 데이터 양이나 파일 크기 감소를 보장하지 않습니다. Docker 정리 추정치·VHDX 크기·Windows 실제 회수량은 서로 다릅니다.

## 표·화면 설정과 CLI

열 제목은 오름차순 → 내림차순 → 원래 순서로 정렬합니다. 상태·종류·정리 가능 여부는 표 위 필터에서 선택하며 정렬·필터는 페이지 분할 전에 적용합니다. 열 경계를 드래그하거나 키보드 방향키로 너비를 조절합니다. 긴 목록은 머리글을 고정한 표 안에서 스크롤하며 창 크기에 맞춰 너비를 조정합니다.

앱은 연결된 엔진의 Docker 이벤트로 외부 Compose·컨테이너·이미지·볼륨·네트워크 변경을 목록에 자동 반영합니다. 이벤트 연결이 복구되면 현재 목록을 다시 읽습니다. WSL 배포판 자체를 외부에서 종료·시작한 경우에는 앱으로 돌아오거나 전체 새로고침으로 연결을 확인합니다. 외부 BuildKit 진행·이력과 이벤트 없는 캐시 변경은 전체 새로고침으로 조회합니다.

**설정 → 화면**에서 언어·테마·글자 크기를 바꿉니다. 엔진·목록을 다시 조회할 때는 앱 상단 **전체 새로고침**을 사용합니다. 설치 후 새 CMD·PowerShell에서 다음 명령을 사용할 수 있으며 포터블은 `bin\docker.exe`를 사용합니다.

```powershell
docker ps
docker compose version
docker buildx version
```

기존 Docker Desktop의 PATH가 먼저이면 위 명령은 기존 Docker 실행 파일을 사용합니다. DockSlate는 실제 설치 폴더의 `bin\docker.exe`를 명시하세요. 기본 설치 위치라면 PowerShell에서 `& "$env:LOCALAPPDATA\DockSlate\bin\docker.exe" ps`, CMD에서는 `"%LOCALAPPDATA%\DockSlate\bin\docker.exe" ps`입니다. 시스템 PATH나 기존 Docker 설정을 자동으로 덮어쓰지 않습니다. 명시한 host·context 옵션은 CLI의 실제 연결 대상을 바꿀 수 있습니다.

설치 EXE 또는 전체 ZIP을 사용하고 배포 파일의 [서명·보안 상태](results/code-signing.md)를 확인하세요. 소스 코드만으로 실행 파일의 서명 여부를 판단할 수는 없습니다.
