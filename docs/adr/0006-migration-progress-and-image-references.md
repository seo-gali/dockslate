# ADR 0006: 가져오기 진행과 이미지 참조 삭제

상태: 채택 · 기록일: 2026-11-26

목록·검사를 하나의 오래 걸리는 IPC 응답에 묶지 않고 진행 중 작업으로 다룬다. inspect는 16개씩 읽으며 시간 초과된 읽기 묶음만 나눈다. 결과가 불명확한 쓰기 명령은 자동 재실행하지 않는다. 승인 유효 시간은 검사가 끝난 뒤 계산하며 승인 후 재검사도 진행 상황을 표시한다.

이전 원본은 고정된 Docker Desktop Linux named pipe로만 연결한다. 이 연결에서 `OSType=linux`와 비어 있지 않은 엔진 ID를 확인하며 표시용 `OperatingSystem`의 제품 문구에 의존하지 않는다. 원본·대상 ID 비교와 실행 직전 동일 엔진 재검사는 유지한다. Windows 컨테이너와 불완전한 응답은 원인을 구분해 거절한다.

완료한 목록·검사 응답은 화면에 전달한 뒤 백엔드 작업 상태에서 제거한다. 진행 상태·복사 결과와 승인에 필요한 대상만 남기며 조회 결과를 전역 캐시로 중복 보관하지 않는다. 이미지 삭제 승인은 ID·태그·digest와 이미지 설정을 비교하되 가변적인 참조 개수·태그 시각 메타데이터는 제외한다.

이전 완료는 성공한 복사 뒤 저장한 식별 기록과 실제 대상이 일치해야 인정한다. 엔진 ID·원본 ID 또는 생성 시각·대상 ID 또는 생성 시각·이전 라벨을 확인한다. 이름만 같은 데이터와 부분 복사본은 재사용하지 않는다. 완료 볼륨·폴더 재사용은 최초 복사본을 쓰는 것이며 원본의 이후 변경을 동기화하지 않는다. 환경 변수·비밀번호는 완료 기록에 넣지 않는다.

다중 태그 이미지는 승인한 태그·digest를 하나씩 해제한다. 참조 컨테이너·메타데이터를 다시 확인하고 새 태그·참조가 생기면 중단한다. 강제 삭제·부모 이미지 정리는 하지 않으며 부분 실패 시 이미 해제한 태그는 자동 복구하지 않는다. 삭제 창에서 대상을 제외하면 기존 승인 정보를 버리고 남은 대상을 새로 검사한다.

앱을 열 때 설치된 전용 엔진을 기본으로 시작하되 사용자 화면 설정에서 해제할 수 있다. Windows 로그인 등록은 기존 명시적 선택을 유지하며, 로그인에서 엔진 시작을 요청한 실행은 화면 설정과 별도로 처리한다. 컨테이너 자동 시작은 별도 실행 목록이나 감시 프로세스 대신 Docker `always`/`no` 정책을 사용한다. 선택한 ID의 정책만 바꾸며 컨테이너를 재생성·즉시 시작하지 않는다.

후속 구현은 컨테이너 화면의 작업 대기열을 사용해 서로 다른 행의 요청을 순서대로 제출한다. 대기 중에도 조회·검색·선택을 허용하며 백엔드 변경 잠금·수정·삭제의 승인 경계는 유지한다. 프로젝트 작업은 전체 구성원을 서버에서 다시 조회하고 의존 순서·healthcheck·성공 종료 조건을 적용한다. 선행 실패 뒤 후속 작업을 실행하지 않는다.

데이터 없는 구성 이전은 최대 16개 컨테이너의 실행 설정을 메모리 안에서 Compose 모델로 변환한다. 일반 목록·복사 작업과 별도 읽기 IPC이며, 기존 Compose 검증·충돌 검사·120초 실행 승인을 재사용한다. 원본 이미지 ID가 대상에 필요하고 새 볼륨은 빈 상태다. 환경 값·명령을 공개 요약이나 로그로 보내지 않는다. `$`는 최종 실행 입력에서 한 번 이스케이프한다. Compose 5.8.0의 [config 출력 처리](https://github.com/docker/compose/blob/v5.8.0/cmd/compose/config.go)는 보간한 결과를 출력할 때 `$`를 다시 이스케이프하므로 오프라인 검사에서는 이 출력 표현과 실제 보간 결과를 구분한다. 원본 데이터 복사는 기존 이전 경로를 사용한다.
