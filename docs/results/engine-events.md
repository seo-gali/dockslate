# Docker 이벤트 자동 갱신

2026-11-05 · 앱 0.1.7. 설치 EXE·ZIP의 제작·공개 검증은 [릴리스 기록](release-0.1.7.md)에서 확인한다.

## 구현

[Docker 이벤트 문서](https://docs.docker.com/reference/cli/docker/system/events/)의 컨테이너·이미지·볼륨·네트워크·daemon 알림을 소유 엔진의 `/events`에서 구독한다. 기존 연결·API 협상·엔진 ID·등록·keeper·경로 검사를 통과한 소켓만 사용한다. 원본 이벤트 속성을 렌더러로 보내지 않고 변경 종류만 전달한다.

Rust에서 250ms 동안 변경 비트를 합치고 프런트엔드에서 500ms 동안 모아 조회한다. 고정된 Docker 병렬 스냅샷을 공유하고 영향을 받은 조회 슬롯에만 반영한다. WSL 인벤토리·빌드 이력은 다시 읽지 않으며, 유휴 상태의 목록 폴링이나 결과 캐시를 추가하지 않았다.

재연결 때 현재 목록을 다시 읽어 이벤트 누락 구간을 보완한다. 페이지 재로딩은 이전 구독을 교체하며, 잘못된 엔진 ID는 기존 구독을 중단하지 않고 거부한다. 엔진 중지·WSL 조작·앱 종료 전 읽기 구독을 정리한다. 이벤트 자동 갱신이 늦은 빌드 조회를 무효화하지 않도록 대시보드와 통계의 요청 세대를 분리했다.

## 실제 검증

`scripts/desktop.ps1 -Mode build`와 locked/offline Rust 검사·TypeScript 빌드가 통과했다. Windows의 실제 네이티브 앱과 전용 엔진에서 **24개 검사 통과**, 렌더러 예외 0건. 실행 파일·명령·검사별 결과는 [구조화된 결과](engine-events.json)에 기록한다.

- 사용자 승인 대상 `dockslate-events-check-7d2a` 컨테이너·네트워크·이미지·볼륨 각 1개를 사용했다. 기존 PostgreSQL 이미지 ID를 고정하고 DB 대신 `sleep`만 실행했다. 포트 공개·다운로드는 없었다. 빈 TAR를 표준 입력으로 전달해 임시 이미지를 만들고, 임시 볼륨에는 데이터를 쓰지 않았다.
- 외부 Compose up·stop·start·down, 컨테이너 rename, 네트워크 create·rm이 수동 새로고침 없이 실제 목록·상태에 반영됐다.
- 잘못된 구독 ID·엔진 ID를 거부한 뒤에도 기존 구독이 동작했다. 앱 화면 재로딩 후 새 구독과 초기 동기화를 확인했다.
- 검증 앱 자신의 WSL 이벤트 읽기 프로세스만 중단했다. 연결 오류 표시 후 구독을 다시 시작하고 현재 목록을 동기화했다. 이 검사와 별도로 실제 런타임 재시작도 수행했다.
- 외부 변경 중 대시보드 전체·BuildKit 이력 조회가 추가되지 않았다. 마지막 변경 뒤 3.5초 유휴 구간에 Docker 목록 조회가 추가되지 않았다. 장시간 부하 결과로 확대하지 않는다.
- 승인한 임시 대상을 정리했다. 기존 사용자 컨테이너 **4개**의 ID·상태, 이미지·볼륨 **2개**·네트워크 목록이 검사 전후 일치했다.

재현 명령은 `node scripts/verify-engine-events.mjs <승인된 격리 네이티브 세션 JSON>`이다. 이 검사는 실제 임시 리소스를 만들고 정리하므로 실행 전에 대상을 승인받는다. 세션의 승인 표시는 사용자 대화의 승인을 대신하지 않는다.

- 외부 image import·rm과 volume create·rm이 현재 화면에 자동 반영됐다. 테스트 라벨을 확인해 임시 대상만 삭제했다.
- `scripts/verify-engine-restart.mjs`로 실제 앱의 런타임 승인 화면에서 DockSlate 배포판만 중지·시작했다. 기존 SQL 컨테이너 3개를 정상 중지한 뒤 같은 ID로 복원했고, 원래 중지된 1개는 유지했다. 엔진 ID·이미지·볼륨·사용자 네트워크 ID와 다른 배포판 상태가 일치하고 건강 상태 확인도 통과했다. Docker 기본 네트워크는 재생성될 수 있어 이름·드라이버·범위로 비교했다. 전체 WSL 종료·커널 변경·DB 쓰기는 없었다.

## 한계

Docker 이벤트가 제공하지 않는 BuildKit 이력·캐시 변경은 수동 새로고침이 필요하다. CPU·메모리는 목록 갱신 시 측정하며 연속 실시간 통계가 아니다. WSL 배포판 자체가 종료된 뒤에는 앱 복귀·수동 새로고침으로 연결을 확인한다.

장시간 부하, 압축, 새 설치·제거는 이번에 실행하지 않았다. 기존 규칙의 수동 조회 한정 문구는 이벤트 구독을 허용하도록 수정했고 유휴 목록 폴링 금지는 유지했다.
