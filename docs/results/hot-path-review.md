# 조회 구조와 핫 패스 점검

2026-11-04 · 개발 소스 0.1.6. 설치 파일·포터블 ZIP·공개 사이트는 이번 작업에서 갱신하지 않았다.

## 변경

- `src/api.ts`: 고정된 11개 조회 종류를 배열 슬롯과 개별 구독으로 관리한다. 중복된 결과 투영 캐시·문자열 키 Map을 제거했다. 빌드 정보와 기본 대시보드 조회를 동시에 시작한다.
- 로그·Inspect·파일·빌드 상세·빌더 검사와 Rust 런타임·보관 기록·Buildx 버전의 전역 결과 캐시를 제거했다. 현재 화면 데이터, 진행 중 요청, 승인·세션·연결 상태는 유지한다. Docker 빌드 캐시와 사용자 리소스는 정리하지 않았다.
- 방문한 메뉴·상세 탭은 비트셋, 컨테이너 그룹은 평탄한 배열로 바꿨다. 통계 작업은 하위 8비트에 요청 인덱스, 상위 8비트에 상태를 넣은 고정 배열과 최대 4개 작업자를 사용한다. 고정 크기 핸들·결과·UTF-16 버퍼도 인라인 배열로 바꿨다.
- Inspect 스크롤은 줄 시작 위치 배열로 표시할 구간만 잘라 갱신한다. 로그 수신은 전체 문자열을 줄 배열로 분리하지 않고 뒤에서 최대 300줄 경계를 찾는다.
- 보관 기록 목록은 상세·로그를 생성하지 않는 요약 파서로 매번 읽는다. 상세는 검증한 `digest:position`에 해당하는 파일·레코드만 읽는다. 엔진 연결은 캐시 대신 등록·소유권·keeper 프로세스를 직접 확인하며 기존 잠금·경로·엔진 확인을 유지한다.

## 순차 I/O 검토

프런트엔드 45개 파일의 await 포함 함수 78개를 AST로 조사하고, 복수 await 또는 루프 안 await가 있는 후보 29개를 확인했다. Rust 21개 파일은 I/O 호출 위치 후보 59개를 추려 호출 관계·입력 검증·변경 순서를 소스에서 확인했다. 이 숫자는 정적 후보 수이며 실행 프로파일이나 모든 간접 호출을 증명하는 호출 그래프가 아니다.

| 경로 | 처리 |
| --- | --- |
| 개요·이미지·디스크·볼륨·네트워크 목록 | 독립 목록·사용량·참조 조회 병렬 실행 |
| 이미지 삭제 미리보기 | 이미지 정보·참조 목록 병렬 실행, 참조 컨테이너 상세는 최대 4개 작업자 |
| 컨테이너 수정 미리보기 | 설정·이름 충돌 조회 병렬 실행, 검증한 볼륨 최대 16개·네트워크 최대 8개는 4개 작업자 |
| Compose 충돌 검사 | 엔진 확인 뒤 컨테이너·네트워크·볼륨·필요한 이미지 조회 병렬 실행 |
| 빌드 정보 | 보관 기록·엔진 연결, 빌더 목록·Buildx 버전 조회 병렬 실행 |
| 로그·설치 완료 확인 | 로그와 TTY 정보, 엔진·Compose·Buildx의 독립 확인 병렬 실행 |
| WSL 종료 후 화면 갱신 | 종료 완료 뒤 인벤토리·새 미리보기 병렬 조회. 압축 완료 뒤 중복 인벤토리 조회 제거 |
| 터미널 입력·스트림 등록·프로세스 수명 | 바이트 순서·이벤트 누락 방지·종료 확인을 위해 순서 유지 |
| 생성·삭제·재생성·전송·실행 | 승인·대상 재검사 → 변경 → 결과·복구 확인 순서 유지 |
| 통계 | 배치 내 최대 4개 병렬 작업자. 프런트엔드 16개 배치는 취소 확인과 요청 폭증 방지를 위해 순서 유지 |

동적 리소스 ID 조인, 압축 형식의 키, 승인 토큰·세션에는 기존 Map을 유지했다. 외부 JSON DTO와 터미널 셀은 함께 소비하는 필드를 가진 객체 배열을 유지한다. 이 부분을 일괄 SoA로 바꾸거나 문자열 ID를 포인터로 대체하면 변환·관리 코드가 늘며 이번 실측으로 이득을 확인하지 못했다.

## 검증

- `npm.cmd run build`: TypeScript·Vite 통과.
- 로컬 Cargo의 `check --manifest-path src-tauri/Cargo.toml --locked --offline`: 통과.
- `powershell -NoProfile -File scripts/desktop.ps1 -Mode build`: 내장 프런트엔드를 포함한 실제 Windows 앱 재빌드 통과. 최신 네이티브 검사 대상 SHA-256은 `E14AA485512763EE5FC6F68FE102EF25617C6885B5478B15E9128C13094069FB`이다.
- 실제 Windows의 동일한 DockSlate 엔진에서 기존·수정 EXE의 읽기 전용 검사 3쌍을 교대로 실행했다. 기존 5,529 / 5,384 / 5,285ms, 수정 4,734 / 4,535 / 4,749ms. 중앙값 **5,384 → 4,734ms, 약 12.1% 감소**. 컨테이너·이미지가 각각 0개인 엔진의 검사 파이프라인 전체 시간이며 개별 API나 부하 환경의 성능 수치가 아니다.
- 여섯 실행 모두 연결·목록·디스크·WSL·런타임 읽기 성공, 승인하지 않은 변경 6종 거부. 기존 컨테이너·이미지·볼륨·Docker 캐시를 삭제하거나 생성하지 않았다.
- 실제 변경 전후 로그 정리 코드를 추출해 경계값·랜덤 스트림 **4,056건**을 대조했다. 결과 일치. 합성 문자열 6,000회 갱신의 5회 중앙값은 **53.48 → 43.87ms**. 실제 컨테이너 로그 처리량을 측정한 결과는 아니다.

재빌드한 실제 Windows 앱을 별도 WebView 프로필·임시 보관 기록 폴더로 실행한 최신 검사 **14개 통과**, 렌더러 예외 0건. 엔진 응답을 대체하지 않았으며 보관 기록만 격리 파일을 사용했다. 아래 결과는 위의 빈 엔진 성능 비교와 별도 실행이다.

- 초기 메뉴만 생성되고 7개 메뉴 방문 상태 유지, 이동에 따른 전체 재조회 없음.
- 빌드 정보·대시보드 IPC의 실제 실행 구간 겹침 확인.
- 통계 요청 256개를 역순으로 전달해 결과 순서 유지, 빈 입력·중복·잘못된 ID·257개 제한 확인. 모두 존재하지 않는 ID이며 실행 중 통계는 검증하지 않음.
- 실제 Rust 파서가 목록에서 상세·로그를 제외하고 선택 레코드를 읽음. 파일 크기·수정 시각이 같은 변경도 재조회에 반영하고, 관련 없는 손상 파일은 선택 상세 조회에 영향을 주지 않음. 잘못된 식별자 7종 거부.
- 실제 표의 키보드 너비 조절이 행 필터 재렌더링 뒤 유지, 빌드 상세 재열기에서 최신 내용 표시.
- 실제 WebView DOM에서 소스의 JSON 표시 함수를 사용한 20개 합성 스크롤·내용 교체·정리 검사 통과. 실제 컨테이너 Inspect 검사는 아님.
- 검사 전후 컨테이너·이미지 목록 일치. 읽기 전용 비교 6회에서도 빌드 캐시 ID·크기와 볼륨 사용량 일치.

수치·검사별 결과·IPC 기록은 [구조화된 결과](hot-path-review.json)에 남겼다. 로컬 검사 도구는 `.analysis/`에서 실행했고 Git에 포함하지 않았다. 문서 링크 414개·앵커 12개, `node --check scripts/verify-inspect-lifecycle.mjs`, `git diff --check`도 통과했다.

## 남은 범위

실행 중인 실제 컨테이너 통계·로그·Inspect·파일·터미널의 전체 사용자 경로, 승인 후 변경·복구, 다수 컨테이너 부하, 설치·제거 전체 회귀는 이번에 실행하지 않았다. 최신 재빌드 검사는 기존 엔진 목록의 전후 일치를 확인했으며 사용자 컨테이너 실행 검사를 통과로 기록하지 않는다. 승인한 DockSlate 전용 엔진은 실행 상태로 유지한다.

기존 조회 수명 문서의 캐시 재사용 지침과 요청 현황의 LRU 설명은 이번 사용자 요청에 맞춰 삭제·정정했다. 과거 검증 기록은 당시 결과로 보존한다.
