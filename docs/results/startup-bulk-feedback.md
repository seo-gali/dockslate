# 자동 시작·컨테이너 일괄 작업 후속 개발

로컬 개발 중이며 공개 0.1.7 설치 파일에는 아직 포함하지 않는다. 실제 확인 결과와 배포 상태를 구분한다.

## 자동 시작 계약

설정에서 엔진 자동 시작과 Windows 로그인 시 DockSlate 창 열기를 독립적으로 선택한다. 기본값은 둘 다 꺼짐이다. 엔진만 선택하면 로그인 때 창 없이 기존 전용 엔진만 시작한다. 둘 다 선택하면 창과 엔진을 시작하며, 창만 선택하면 엔진을 임의로 시작하지 않는다. 엔진 자동 시작은 사용자가 직접 앱을 열 때도 적용한다.

[Windows 현재 계정의 Run 항목](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys) `DockSlate`에 현재 실행 파일과 고정된 `--startup engine|app|both` 인수만 등록한다. 같은 경로의 관리되는 명령만 변경·삭제하며 다른 명령은 보존하고 충돌을 표시한다. 앱 제거 시 같은 설치 경로의 등록만 제거한다. 재설치 후 등록이 없으면 두 옵션은 꺼짐으로 표시한다. Run 명령은 Windows 제한인 260자를 넘으면 등록 전에 거부한다.

설정 변경 자체는 현재 엔진이나 창을 중지·시작하지 않는다. 실제 자동 시작은 새 앱 실행·Windows 로그인 때 적용한다. 기존 엔진 소유권·등록·경로 검사를 재사용하며 자동 설치는 하지 않는다. 설치 준비창과 관리자 작업용 재실행에서는 자동 시작을 생략한다. 이미 설치된 중지 엔진을 첫 설치로 표시하지 않고, 연결 후 메인 화면으로 이동한다.

## 일괄 작업 계약

컨테이너 표에 행·검색 결과 전체 선택 체크박스와 시작·중지·재시작 버튼을 제공한다. 전체 선택은 필터 결과 전체 페이지를 대상으로 한다. 검색·필터를 바꾸면 선택을 비우고, 정렬만 바꾸면 유지한다. 시작은 이미 활성 상태인 대상을, 중지·재시작은 중지된 대상을 건너뛴다.

고유한 컨테이너 ID 1~256개를 받고 작업 종류·ID를 실행 전 검증한다. 소유 엔진의 현재 목록을 한 번 읽고 최대 4개 작업자로 처리한다. 단일 작업의 상태 검사·실행 코드를 공유하고, 결과는 항목별 완료·건너뜀·실패로 반환한다. 부분 실패 때 성공한 작업은 유지하고 실패 항목을 선택한 채 사유를 표시한다. 전체 대시보드는 작업 뒤 한 번 갱신한다. 기존 컨테이너 재시작 정책은 바꾸지 않는다.

## 확인 상태

- `npm run build`: TypeScript·Vite 빌드 종료 0.
- `cargo check --manifest-path src-tauri/Cargo.toml --locked --offline`: 종료 0. 기존 로컬 도구 체인 사용, 의존성·lock 변경 없음.
- `powershell -NoProfile -File scripts/desktop.ps1 -Mode build`: 오류 문구·여백·작업 중 종료 방지 수정을 포함한 최종 Windows 네이티브 앱 빌드 종료 0.
- `powershell -NoProfile -File scripts/verify-installer-path.ps1`: 실제 Windows 임시 레지스트리 키에서 9개 검사 종료 0. 네 가지 소유 자동 시작 명령 제거, 다른 경로·인수·명령·형식 보존 확인. 실제 사용자·시스템 PATH 변경 없음. 샌드박스에서는 키 접근이 거부되어 일반 사용자 환경에서 실행했다.
- 네이티브 UI에서 독립된 두 설정의 꺼짐 기본값, 전체·개별·일부 선택 표시, 상태에 맞는 버튼, 검색 변경 시 선택 해제 확인. 빈 목록·중복·잘못된 ID·257개·미지원 작업 거부 확인. 컨테이너 변경·자동 시작 등록 없이 렌더러 예외 0건.
- `node scripts/check-workflow-pins.mjs`: workflow 2개·외부 참조 6개·자체 검사 25개, 오류 0.
- 최종 네이티브 앱에서 1500×975·1000×640 문서 가로 넘침 없음, 영어 자동 시작 레이블 확인 후 한국어 원복. 영어 탭 이름을 잘못 찾은 검사 스크립트의 원복 단계는 선택자 수정 후 종료 0으로 재검증했다.
- 자동 시작 등록이 없는 상태의 `--startup engine`은 종료 0, 미지원 `--startup invalid`는 종료 1. 실제 엔진 자동 시작 성공으로 합산하지 않는다.
- 최종 조회에서도 기존 SQL 컨테이너 네 개는 같은 ID·실행 상태이며 실제 DockSlate 자동 시작 등록 없음. [구조화 결과](startup-bulk-feedback.json)에 최종 로컬 실행 파일 SHA와 검사 범위를 기록한다.

실제 일괄 실행·자동 시작 등록·엔진을 켜는 자동 시작 명령은 승인 대기다. 검사 스크립트 `scripts/verify-container-batch.mjs`는 승인 범위가 명시된 세션에서만 격리 컨테이너 두 개를 생성·시작·중지·재시작·정리한다. 기존 SQL 컨테이너 네 개는 조회 당시 모두 실행 중이다. 엔진 재시작 검증은 정상 중지·동일 컨테이너 복원의 영향을 승인받은 뒤 수행한다. 실제 로그인·Windows 재부팅·설치 EXE 재배포를 통과로 기록하지 않는다.

## 마지막 검토와 수정

중지된 기존 엔진을 첫 설치 화면으로 보내던 경로를 고쳤다. 재시작 후 비정상 종료에 완료 문구가 나오지 않도록 단일·일괄 작업의 공유 코드를 수정했고, 작업 중 창 종료를 막았다. 설정 하단 여백도 조정했다. 공개 0.1.7의 파일과 태그는 덮어쓰지 않았으며 공개 사이트 반영 확인이 남아 있던 기록은 실제 CI·HTTP 근거로 갱신했다. DESIGN의 Pages 직접 다운로드 설명은 현재 GitHub Release 연결과 기존 주소 보존 동작으로 정정했다. 삭제 파일은 없다.
