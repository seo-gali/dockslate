# 설치 전 기존 버전 제거 실패

2026-11-11. 사용자 화면의 `NSIS Error: Error launching installer` 뒤 `제거할 수 없습니다!`를 조사했다. 실행 중인 설치 파일은 0.1.10, 기존 설치는 0.1.9다. 기존 제거 EXE와 제거 명령은 존재하지만 `HKCU\Software\DockSlate\DockSlate`의 설치 폴더 기본값이 32·64비트 보기 모두 없었다. 이 값이 없어진 원인은 확인되지 않았다.

Tauri의 기존 버전 제거 경로는 이 기본값을 읽어 `uninstall.exe _?=<설치 폴더>`로 호출한다. 빈 값은 `_?=`가 되어 NSIS 초기화에서 거부된다. [NSIS 명령행 계약](https://nsis.sourceforge.io/Docs/Chapter3.html#uninstallerusage)과 [3.11 초기화 코드](https://github.com/kichik/nsis/blob/v311/Source/exehead/Main.c#L299)를 대조했다. `InstallLocation`의 바깥 따옴표는 Tauri가 쓰는 정상 형식이며 이번 결함으로 취급하지 않는다.

수정은 재설치 화면이 열리기 전에 누락된 기본값만 복원하는 `src-tauri/installer/hooks.nsh`의 MUI 초기화 hook이다. 기존 제거 등록의 절대 경로·제거 명령·앱·제거 EXE가 일치할 때만 복원하며, 이미 있는 값이나 확인할 수 없는 등록은 덮어쓰지 않는다. 기본 설치 대상도 복원한 기존 폴더를 따르되 별도로 지정한 다른 설치 위치는 유지한다. **버전 번호는 복원 조건에 사용하지 않는다.** Tauri의 기존 버전 비교·다운그레이드 제한은 그대로다.

조사 당시 이 PC에서는 기존 0.1.9의 앱·제거 EXE·등록 명령을 재검사하고 제품 키의 기본값 하나만 복원했다. 언어·제거 명령·앱 파일은 유지했으며 제거 EXE의 SHA-256은 복원 전후 `BED03A50CAA5E3E09B026255AF57FCC60D57C18E9EA6B6BF648A92E58D15DE6A`로 같았다. 이 0.1.9는 관찰된 설치 버전이며 복원 가능한 버전을 제한하지 않는다.

검증:

- 격리 NSIS 3.11 제거 EXE에서 빈 `_?=`는 종료 2, 제거 Section 미진입을 재현했다. 공백을 포함한 정상 절대 경로는 종료 0과 시험 Section 진입을 확인했다. 실제 설치본의 제거 EXE는 실행하지 않았다.
- `powershell -NoProfile -File scripts/verify-installer-upgrade.ps1`: 종료 0, [13개 검사](installer-upgrade.json) 통과. 실제 MUI 초기화가 페이지보다 먼저 실행되는지, 0.1.1·0.1.9·0.1.10·9.9.9 등록, 따옴표 유무·기존 값과 언어 보존·기본/별도 위치, 불일치 명령·상대 경로·제거 EXE 누락의 거부를 확인했다. 운영 키 대신 GUID 시험 키를 사용하고 시험 후 제거했다.
- 최초 환영 화면 fixture 컴파일은 로컬 NSIS의 기본 bitmap 읽기 실패로 중단돼 통과에 합산하지 않았다. 이미지가 불필요한 실제 MUI 설치 페이지로 초기화 순서를 검증했다. 전체 설치판 패키징 성공을 뜻하지 않는다.

이 조사에서는 실제 앱 제거·업그레이드·새 설치판 재빌드·엔진 변경·백신 예외 추가를 수행하지 않았다. 이후 hook을 포함한 새 설치판 제작은 [0.1.13 기록](release-0.1.13.md)에 있으며 실제 전체 제거·업그레이드 검증은 여전히 별도다. 이 hook 수정은 기존 EXE에 소급 적용되지 않는다. 0.1.10 설치판의 이전 Microsoft 탐지로 인한 공개 배포 보류와는 별개인 경로 오류이며, 이 수정이 탐지를 해소했다고 판단하지 않는다.
