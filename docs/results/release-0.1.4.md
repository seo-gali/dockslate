# 0.1.4 로컬 검증

설치 EXE·공개 다운로드는 아직 0.1.3이다. 0.1.4는 아래 화면 변경을 검증한 로컬 후보이며, GitHub 설치 파일 빌드와 게시를 실행하지 않았다.

## 변경과 실제 확인

- Dockerfile 선택 후 자동 빌드, `다시 빌드`, 진행 중인 빌드에서 로그로 이동을 실제 확인했다. 파일 선택 시 자동 빌드하는 기존 동작은 유지한다.
- Dockerfile·Compose의 `파일 선택 닫기`를 오른쪽 아래에 맞췄다. 닫으면 선택과 이전 결과를 지우고 엔진의 이미지·빌드 기록은 유지한다.
- 가져온 Compose 프로젝트는 짧은 표시명을 사용하고 펼침 영역에서 전체 내부 이름을 확인한다. 실제 프로젝트 이름·충돌 검사·소유권 검사는 변경하지 않았다.
- `진행 중인 빌드`·`빌더 관리`로 메뉴를 구체화했다. 실제 진행 중인 앱 빌드만 표시하며, 빌더 관리에는 다음 빌드 환경을 고르는 목적을 표시한다.
- 컨테이너의 Compose 그룹은 마우스와 Enter로 접고 펼칠 수 있다. 일반 프로젝트 이름은 그대로 표시한다. Dockerfile 컨테이너는 Compose 그룹 대신 단독 컨테이너에 속한다.
- 정리 표의 헤더 체크박스는 검색·필터에 맞는 선택 가능 항목만 선택한다. 일부 선택 표시, 필터 밖 선택 유지, 차단 항목만 있는 경우 비활성화를 실제 확인했다. 페이지 분할 전에 선택 범위를 계산한다.
- 공통 확인창 최대 너비는 1040px, 최대 높이는 680px이며 작은 창에서는 여백을 제외한 크기로 줄어든다. 이미지 삭제 대상은 가로 카드로 배치하고 내용만 내부 스크롤한다. 이미지 참조 검사 완료 후 1668×900·1000×640에서 승인 영역과 하단 버튼이 창 안에 있는 것을 확인했다.

[실제 Windows 앱 검사 10개](ui-workflow-0.1.4.json). 앱 SHA-256: `7AD08317387307F4F50B15655DF02E3AC39FDBB272B181D632BB2691C41E01E2`.

## 설치 파일 상태

`powershell -NoProfile -File scripts/build-installer.ps1 -SkipBuild`를 일반 사용자 환경에서 실행했으나 종료 1이다. NSIS가 `src-tauri/installer/user-path.ps1`을 열지 못해 설치 파일 생성이 중단됐다. 파일명 변경·보안 설정 변경·우회는 하지 않았다. 현재 0.1.4 설치 EXE는 없으며, 공개 0.1.3 파일을 교체하지 않았다. 이전 GitHub 설치 파일 빌드 승인은 0.1.3 1회에 한정되어 사용을 완료했다.

이미지 삭제 확인은 기존 Mongo 이미지를 포함한 미리보기를 취소했으며 삭제를 실행하지 않았다. 처리 중 진행 표시의 새 배치, 새 설치·제거, 전체 회귀와 DB 동작은 이번 검증에 포함하지 않았다. HTML 안내서 브라우저 검사는 디버깅 세션 부재로 시간 초과했으며 통과로 계산하지 않는다. 설치판 서명과 기존 보안 경고는 미해결이다.
