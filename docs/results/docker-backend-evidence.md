# Docker backend 구현 추가 근거

2026-10-13. 기존 [v1.24.0 REA 기록](../research/rancher-desktop-1.24.0.md)과 Evidence는 보존한다. 전체 ASAR 재분석과 Rancher Desktop 실행은 수행하지 않았다.

- **기존 배포 파일의 추가 읽기 전용 확인:** `.analysis/rancher-desktop/v1.24.0/msi-readonly/msi-inventory.json`의 File→Component→Directory 관계에서 `docker.exe`는 `resources/resources/win32/bin/docker.exe`, `wsl-helper.exe`는 `resources/resources/win32/internal/wsl-helper.exe`임을 확인했다. 파일 ID는 각각 `f_MRvzeVx9z6qIdJLyFR7fxCJNyYNOCjLPQYSDhu1dxxw`, `f_HbNoUTvIErGqbKDLBhvymVnhPK1f1Hcdc10kubPudSU`이다. 설치하지 않고 보존된 MSI 인벤토리만 조회했다.
- **공개 소스 확인:** [Rancher Desktop v1.24.0 WindowsIntegrationManager](https://github.com/rancher-sandbox/rancher-desktop/blob/v1.24.0/pkg/rancher-desktop/integrations/windowsIntegrationManager.ts#L116)는 Windows `wsl-helper`를 `docker-proxy serve` 인수로 실행한다. 기존 REA 보고서의 Windows Moby endpoint는 `npipe:////./pipe/docker_engine`이다.
- **DockSlate 독자 설계:** uninstall 레지스트리의 Rancher Desktop/SUSE 등록과 설치 실행 파일을 확인하고, named pipe 서버 PID의 실제 실행 경로를 등록된 설치의 `wsl-helper.exe`와 비교한다. 동일 pipe 이름을 쓰는 Docker Desktop은 연결 대상에서 제외한다. Docker context show/inspect는 해당 설치의 고정된 CLI로 조회하며 endpoint만 추출한다. `DOCKER_HOST` 및 TLS 관련 override가 설정되면 연결을 차단한다. 컨텍스트·소유자·Linux Engine·API 범위·Engine ID를 검증하지 못하면 작업을 차단한다.
- **공개 소스 확인 / 선택 cache 삭제:** [Moby 28.5.1 builder.go](https://github.com/moby/moby/blob/v28.5.1/builder/builder-next/builder.go#L607)는 cache `id` 필터를 BuildKit의 `id~=` 정규식으로 변환하며 필드마다 하나의 값만 허용한다. 해당 버전의 [vendor.mod](https://github.com/moby/moby/blob/v28.5.1/vendor.mod#L63)가 지정한 [BuildKit 0.25.1 manager.go](https://github.com/moby/buildkit/blob/v0.25.1/cache/manager.go#L1044)는 참조가 없는 cache와 필터에 맞는 레코드를 prune 대상으로 선정한다. `all=false`에서는 internal/frontend/shared 레코드를 제외한다. DockSlate는 사용·공유 상태를 재검증하고 선택 ID마다 `^ID$` 필터와 `all=false`를 사용한다. ID는 영문·숫자로 제한한다. BuildKit의 `inuse`·`shared` adapter는 문자열 bool equality가 아니라 존재 여부이므로 `inuse=false`/`shared=false` equality 필터를 전달하지 않는다.
- **추가 공개 API 근거 / 독자 설계:** [Docker API 1.51 명세](https://raw.githubusercontent.com/moby/moby/v28.5.1/api/swagger.yaml)의 `/build/prune`는 `id` 필터를 명시한다. 실행 Engine이 `MinAPIVersion <= 1.51 <= ApiVersion`을 광고한 경우에만 선택 cache 삭제를 허용하며 해당 요청은 `/v1.51/build/prune`으로 고정한다. 다른 조회는 협상한 API를 사용한다. 이는 공개 API 호환 계약에 근거한 설계이며 최신 Engine 내부 구현이나 실제 prune 성공을 확인했다는 뜻은 아니다. [v1.24.0 dependencies.yaml](https://github.com/rancher-sandbox/rancher-desktop/blob/v1.24.0/pkg/rancher-desktop/assets/dependencies.yaml#L96)의 CLI 29.6.2는 실제 Engine 버전의 증거가 아니며, 해당 버전의 내부 builder 파일 조회는 404였다.
- **추가 공개 API 근거 / Pull:** 같은 API 명세의 `/images/create`는 태그와 digest가 모두 없으면 전체 태그를 다운로드한다고 명시한다. DockSlate는 태그 없는 입력의 마지막 경로 구성 요소에 `:latest`를 붙인다. registry 포트와 이미지 태그를 구분하고 digest는 유지한다. 완료 후 `/images/{reference}/json`으로 Engine이 정규화한 실제 이미지 ID를 확인한다. 로그인·credential 값 출력·인증 헤더 전달 기능 없이 공개 이미지 Pull만 지원한다. 컨텍스트 조회는 설치된 Docker CLI의 기존 설정 읽기 동작을 사용한다.
- **DockSlate 독자 설계 / 삭제 안전성:** 삭제 preview는 정확한 ID 목록·영향·복구 불가·2분 만료 시각을 반환한다. Windows CSPRNG로 생성한 token은 한 번만 소비하며 `approved=true`가 필요하다. Engine ID/context/소유자와 대상 참조·사용 상태를 실행 직전 재검증한다. 컨테이너 삭제는 stopped 상태에서 `force=0&v=0`, 이미지 삭제는 `force=0&noprune=1`이다. container/volume/system 일괄 prune과 force 삭제는 구현하지 않는다.

실제 Rancher Desktop Moby Engine이 없는 현재 환경에서 성공 연결·목록·Pull·시작/중지·삭제·선택 cache prune은 E2E 검증할 수 없다. 기존 Docker Desktop 데이터에는 API 조회나 변경을 수행하지 않는다. 위 코드는 실제 Engine에 대한 동작 검증 완료를 의미하지 않으며 Windows 빌드·연결 실패 경로 검증 결과는 상위 구현 기록에서 별도로 보고한다.
