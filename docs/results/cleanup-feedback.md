## 변경 범위

- `src/actions.tsx`: 완료·실패 건수는 짧은 본문으로 유지하고 대상 이름·한국어 사유·ID는 접을 수 있는 실패 목록에 표시한다. 일부 완료는 경고, 전부 실패는 오류로 구분한다.
- `src/pages/DockerUsage.tsx`: 실패 알림에서 목록 재조회를 제공한다. 조회 실패로 이전 데이터만 남아 있으면 선택·정리를 차단하고 상태 확인 필요로 표시한다.
- `src-tauri/src/docker.rs`: 다른 캐시에서 참조하는 부모 캐시를 선택 대상에서 제외한다. 실제 엔진 응답에서 확인한 ` Parents` 키와 표준 `Parents`·구형 `Parent`를 처리한다. 미삭제 결과는 엔진이 유지했다는 사실과 상태 확인 조치로 표현한다. 선택 ID 필터·실행 직전 재검사·`all=0`은 유지한다.
- `src/ComposeImport.tsx`, `src/ComposeImportPanel.tsx`, `src/ImageBuildPanel.tsx`, `src/pages/Builds.tsx`: 공통 파일 선택 카드 안에 현재 형식의 설정·결과만 표시하고, 전환 시 이전 가져오기 선택을 해제한다. 선택 취소 시 기존 결과를 유지한다.
- `src/styles.css`: 긴 WSL 디스크·파일 빌드 화면의 아래 여백을 유지한다. 표 화면의 높이 제한은 유지한다.
- `src/locales.ts`, `src/locales.en.ts`, `DESIGN.md`: 한국어·영어 오류 사유·다음 조치와 화면 규칙을 맞췄다.

## 확인한 원인과 경계

사용자가 제시한 Node.js 캐시 `sbb31q4lydqqckam94wll41vh`는 조사 시 `Shared: true`였다. 이는 이미지와 공유하므로 현재 선택 대상에서 제외되어야 한다. 과거 실패 당시의 전체 상태는 남아 있지 않아 같은 상태였다고 단정하지 않는다. ‘선택 가능’은 조회 시점의 검사 결과이며, 실행 직전 다시 검사한다. 실행 전후 참조가 변하면 엔진이 유지를 결정할 수 있다.

폴더 삭제 차단은 파일 식별자를 대조한 결과 Windows 탐색기 `explorer.exe` PID 10284의 폴더 핸들 2개로 확인했다. COM 조회에서도 해당 폴더를 연 탐색기 창을 확인했다. 원본 핸들을 닫거나 탐색기를 종료하지 않았다. 다른 계정·보호된 프로세스의 모든 핸들을 열람한 검사는 아니다.

## 실제 검증

프런트엔드 빌드, Rust 검사와 Windows 릴리스 빌드는 모두 종료 0이다. 실제 EXE SHA-256은 `5D18F9EAB116A69F8EE7D983973D8A81582D2C2764E3D36F01C14BA1DF1310F1`이다.

- 실제 Windows 검사 12개: 두 창 크기의 아래 여백, 단일 빌드 카드, 실제 공유 캐시 차단, Dockerfile→Compose→Dockerfile 전환, 선택 취소·닫기, 실제 부모 캐시 차단과 선택 캐시 정리.

- 전용 scratch 빌드 세 번으로 만든 이미지 3개만 제거했다. 표식·소스 파일명·이전 캐시 목록으로 확인한 캐시 1개를 실제 UI에서 승인·정리했다. 삭제하지 않은 모든 캐시가 남았고 기존 컨테이너 ID·상태·이미지·볼륨을 대조했다. 테스트 컨테이너·새 네트워크·볼륨은 만들지 않았다.
