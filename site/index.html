GET STARTED

첫 설치부터 실제 작업까지.

Node.js와 Rust는
앱 사용자에게 필요하지 않습니다.

설치 EXE로 시작하세요.

  1. 파일 다운로드

    아래에서 Windows x64 설치 EXE를 받습니다. 현재는 미서명 개발 빌드입니다.

  2. 앱과 엔진 준비

    설치 중 엔진 대상과 영향을 확인하고 동의하면 전용 Docker Engine의 설치·시작을 이어서 진행합니다.

  3. 새 터미널에서 확인

    설치가 끝나면 새 CMD 또는 PowerShell 창에서 Docker 명령을 확인합니다.

PowerShell / CMD
docker ps
docker compose version
docker buildx version
필요한 환경

Windows 11 x64 · WSL 2.4.10 이상 · WebView2
첫 엔진 설치에는 인터넷 연결이 필요합니다. WSL 기능 설정에 따라 재시작이 필요할 수 있습니다.

이미지를 받고 실행합니다.

  1. 이미지 준비

    이미지 메뉴에서 Docker Hub를 검색하거나 이미지 이름과 태그를 입력해 받습니다.

  2. 실행 설정

    로컬 이미지의 실행 버튼을 눌러 이름, 포트, 볼륨 등 필요한 항목을 설정합니다.

  3. 상태와 로그 확인

    컨테이너 메뉴에서 실행 상태를 확인합니다. 이름을 누르면 상세·로그·터미널·파일이 열립니다.

PORT MAPPING
내 PC 포트→컨테이너 포트

자동 할당된 포트를 썼다면 컨테이너 표에 표시된 내 PC 포트로 접속하세요. MongoDB 같은 데이터베이스 포트는 웹 페이지가 아닙니다.

실행하자마자 중지되나요?

hello-world는 메시지를 출력하고 종료하는 이미지입니다. 상세의 종료 코드와 로그를 함께 확인하세요.

프로젝트 파일로 빌드합니다.

  1. 파일 가져오기

    빌드 메뉴에서 Dockerfile 또는 Compose 파일을 선택합니다.

  2. 설정 확인 후 빌드

    프로젝트와 지원되는 구성을 확인합니다. Dockerfile의 부모 폴더가 기본 빌드 컨텍스트입니다.

  3. 결과 확인 후 실행

    생성된 이미지 또는 Compose 구성을 확인하고 실행 대상을 승인합니다.

프로젝트 폴더에서 사용하는 CLI 예시
docker build -t my-app .
docker compose up -d
Compose 가져오기 범위

프로젝트 내부 상대 경로, 새 named volume, bridge 등 제한된 구성을 지원합니다. 임의의 Kubernetes YAML 배포나 모든 Compose 옵션을 지원하는 것은 아닙니다.

익숙한 Docker 명령 그대로.

  1. 새 터미널 열기

    설치판은 현재 사용자 PATH에 DockSlate의 bin 폴더를 등록합니다. 설치 전에 열었던 터미널은 다시 열어주세요.

  2. 엔진 상태 확인

    앱의 설정 → 런타임에서 전용 엔진이 실행 중인지 확인합니다.

  3. 평소 명령 사용

    Windows Docker CLI·Compose·Buildx가 포함됩니다. 포터블에서는 압축을 푼 폴더의 bin\docker.exe를 사용합니다.

PowerShell / CMD
docker ps
docker images
docker compose version
포터블로 사용한다면

ZIP 전체를 압축 해제하고 DockSlate.exe, bin, libexec를 같은 폴더에 유지하세요.

GOOD TO KNOW

설치 전에 궁금한 것들.

Docker Desktop을 따로 설치해야 하나요?

별도로 설치할 필요가 없습니다. DockSlate는 전용 WSL 2 배포판 안에서 Moby 기반 Docker Engine을 실행합니다. 앱과 Windows Docker CLI를 설치하고, 승인한 대상에 엔진을 준비하는 구성입니다.

WSL 없이도 Linux 컨테이너를 실행할 수 있나요?

현재 DockSlate의 Linux 컨테이너 엔진은 WSL 2를 사용합니다. Windows 11 x64와 WSL 2.4.10 이상이 필요합니다. 이 페이지나 HTML 파일 자체가 엔진을 실행하는 것은 아닙니다.

앱을 삭제하면 이미지와 볼륨도 지워지나요?

앱과 전용 WSL 데이터는 별개입니다. 앱 제거 또는 포터블 폴더 삭제로 WSL 배포판·이미지·볼륨을 자동 삭제하지 않습니다. 엔진 중지도 데이터를 삭제하지 않습니다.

MongoDB 연결이 거부되면 무엇을 확인하나요?

컨테이너가 실행 중인지 확인하고, 표에 표시된 내 PC 포트를 사용하세요. 예를 들어 127.0.0.1:32768 → 27017이면 Compass 연결 주소는 mongodb://127.0.0.1:32768입니다. 실제 할당된 포트는 컨테이너마다 다를 수 있습니다.

미서명이면 악성코드인가요?

미서명은 검증된 게시자 서명이 없다는 뜻이며, 그 자체로 악성코드 판정은 아닙니다. 반대로 서명이 있다고 안전성이 보장되는 것도 아닙니다. DockSlate의 이전 접근 경고는 아직 원인 미확인이며, 이 페이지에서 보안 보호 해제나 예외 등록을 권하지 않습니다.

현재 어느 정도까지 검증됐나요?

개발 환경에서 엔진 연결·컨테이너·로그·표 조절과 Windows 명령을 확인했습니다. 모든 PC에서의 설치·제거와 모든 Docker 기능을 검증한 제품은 아닙니다. 지원 범위와 미검증 항목은 요청·검증 현황에서 확인하세요.
